# UI08-R5 — план ресурсов и месячного меню (предложение)

Статус: HTML для согласования, 2026-11-02. В Unity ничего не изменено.
Самодостаточный макет: docs/prototypes/stock-review-v1/Serenity-Stock-Review.html.
Этот перечень собирается из catalog.js той же командой, что HTML, чтобы правила не расходились.

## Решения пользователя

- Сначала HTML и план по каждому ресурсу; внедрение только после одобрения.
- Ручные цели сохраняются. Добавляются кнопка «Рассчитать автоматически», приоритет и процентный резерв.
- Питание: один открытый вид блюда на день, по 3 порции каждому, план на месяц.
- Первый день — жареная рыба, второй — жареное мясо. Отдельная свинина не нужна.
- Лук планируется для охотников, меч — для соответствующих военных, еда — для всех жителей.

## Верхняя панель

Две устойчивые строки. В первой поселение, календарь/погода, управление временем и отдельная ячейка
уведомлений/настроек. Во второй шесть групп ресурсов. Количество ресурсов не меняет число кнопок.
Плашка доступна при наведении, фокусе или нажатии, остаётся открытой при переходе курсора внутрь,
имеет собственную прокрутку, полные числа и переход в запасы. Escape/кнопка закрытия доступны.
Большие числа сокращаются только в HUD; исходные количества доступны в плашке. Итоги группы —
единицы предметов, а не сумма пищевой ценности. Дни еды считаются только по готовым блюдам.
На узком экране группы переходят в две строки, а не исчезают; элементы уведомлений не абсолютно
позиционируются поверх даты или режима. В макете есть сценарии 10 000 каждого вида и пустых складов.

## Месячное меню и оперативные цели

Месяц в примере = 30 дней (настраивается 1–31); это проектное окно, а не новая календарная authority.
48 жителей × 3 порции × 30 дней = 4 320 порций. При четырёх открытых блюдах: 8 дней рыбы, 8 дней мяса,
7 дней ягод, 7 дней вяленого мяса. Все дни редактируются. Закрытый рецепт исключается, его дни
переназначаются из оставшихся открытых. Если нет открытых блюд, расчёт показывает блокер и не применяется.

Месячные показатели блюд и сырья — полный план без вычета имеющегося склада. Разовый спрос на
снаряжение не умножается на 30; учитываются роли, резерв и уже выданные исправные вещи.
Корм считается по животным: сумма ceil(животных в загоне / 3) по загонам × дни.
Лекарства: предлагаемая норма 2 на активный случай + ceil(жителей / 10) общего резерва, не прогноз
30 одинаковых эпидемий. Эти нормы лечения/снаряжения требуют подтверждения адаптеров при реализации.

Оперативный склад по умолчанию покрывает ближайшие 3 дня меню, регулируется отдельно до 30.
Процент запаса увеличивает конечные складские нужды. Месячные порции сами по себе не увеличиваются.
Можно выбрать весь месяц, но в игре должны проверяться срок хранения и вместимость. 3 дня —
пример настройки, не гарантия свежести. Производство по дням и партиям не означает хранить весь месяц
свежих блюд сразу. Надбавка сырья по умолчанию 0%, чтобы не множить резерв на каждом шаге цепочки;
индивидуальная надбавка сырья возможна, и дополнительный спрос проходит к входам его рецепта.

Конечный дефицит разворачивается назад по существующим рецептам, с округлением партий вверх.
Склад готового продукта вычитается до расчёта входов. Общие входы суммируются, доступные полевые
туши используются как замена, побочные шкуры/кости учитываются один раз. Сметы включают только
подтверждённые незавершённые работы за вычетом уже доставленных/зарезервированных материалов.
Ожидаемые доставки и выданные вещи в игре должны иметь канонические источники; в примере доставки = 0.

## Ручные значения, приоритет и применение

Изменение числа цели переводит строку в ручной режим. Расчёт показывает список изменений,
затем применяется отдельной кнопкой только к автострокам. Слишком низкая ручная цель сырья
не исправляется молча: выводится предупреждение, что она ограничивает план.
Возврат в авто и изменение процентов/горизонта требуют нового применения.
После применения опциональное обновление пересчитывает автоцели при изменении состава поселения.
Ручные цели сохраняются. Приоритет меняет очерёдность удовлетворения дефицита, а не объём рациона;
в HTML он упорядочивает список предлагаемых изменений. Реальных заданий рабочим макет не создаёт.
Переполнение склада показывается явно, цели не обрезаются; в игре нужна проверка фильтров отдельных складов.

## Аудит источников и границы

- Assets/Game/Art/Config/ResourceCatalog.asset: 42 записи; water исключена по указанию пользователя.
- Assets/Game/Domain/Production/ProductionModels.cs: реальные входы/выходы готовки, разделки, одежды,
  щитов, копий, луков, стрел, лекарств и концентрированного корма.
- Assets/Game/Simulation/Production/ProductionService.cs: съедобны только cooked_berries, cooked_fish,
  cooked_meat, dried_meat; текущая базовая норма 2/сутки. Запрошенные 3/сутки пока только в предложении.
- Там же концентрат покрывает до 3 животных; запасной корм wheat/plant_fiber/berries выбирается как
  альтернативный путь, не прибавляется параллельно. В примере используется только концентрат.
- combat_bow сейчас боевой предмет; использование охотниками — желаемая привязка, а не уже выполненная.
- Меч отсутствует в каталоге. Будущий план: один на военного с мечевым комплектом + резерв − выданное;
  копьё и меч не суммируются на один основной слот. Без действующей цепочки автоцель будущего меча = 0.
- Все товары категории Food не автоматически считаются готовыми блюдами. Нет выдуманных рецептов
  для молока, яиц, овощей или сырой нефти. Вода не возвращается в HUD и запасные цели; вода загонов —
  отдельное существующее состояние, которое этот макет не меняет.
- FRS FR-LOG-001/002, FR-PROD-001, FR-WORK-003: физические запасы, фильтры складов, цепочки и групповые работы.
- Все цифры склада/ролей/выданного — демонстрационные; никакого доступа к игровым сохранениям.

### Еда

| Ресурс | ID | Потребитель и правило |
|---|---|---|
| Жареное мясо | cooked_meat | Все жители. 3 порции на каждого в день этого блюда. Второй день цикла. Два блюда из 2 мяса и 1 бревна. |
| Жареная рыба | cooked_fish | Все жители. 3 порции на каждого в день этого блюда. Первый день цикла. Два блюда из 2 рыбы и 1 бревна. |
| Приготовленные ягоды | cooked_berries | Все жители. 3 порции на каждого в назначенные дни. Три блюда из 3 ягод и 1 бревна. |
| Вяленое мясо | dried_meat | Все жители и снабжение. 3 порции на каждого в назначенные дни. Две порции из 3 мяса. Отряды не считаются второй раз, если их люди уже в населении. |
| Сырое мясо | meat | Костры, кухни, сушилки. Сырьё только под недостающие жареные и вяленые блюда. Не считается готовой едой. |
| Сырая рыба | fish | Костры и кухни. Сырьё под недостающую жареную рыбу; запас готовых блюд уже вычтен. |
| Ягоды | berries | Готовка; резервный корм. Сырьё для ягодных блюд. Корм добавляется только при выбранной замене концентрата, не одновременно. |
| Туша животного | carcass | Охотники и разделка. Одна туша на недостающую освежёванную. Короткий оборот, а не запас туш на каждого жителя. |
| Освежёванная туша | dressed_carcass | Мясники. Одна туша даёт 5 мяса и 3 кости. Учитывать уже доставленные туши и годные туши в обработке. |
| Разделанная в поле туша | field_dressed_carcass | Мясники. Цель 0: использовать наличные как замену по выходу 3 мяса и 1 кость, не заказывать параллельно обычную тушу. |
| Морковь | carrot | Будущие блюда / ручной заказ. Автоцель 0 до подключения действующего рецепта питания. Категория Food ещё не означает съедобность. |
| Капуста | cabbage | Будущие блюда / ручной заказ. Автоцель 0 до подключения действующего рецепта; ручная цель остаётся доступна. |
| Грибы | mushrooms | Будущие блюда / ручной заказ. Автоцель 0: сейчас нет блюда в списке потребляемой пищи. |
| Молоко | milk | Продукт животноводства. Автоцель 0 без подтверждённого потребителя. Не увеличивать стадо ради заполнения произвольной нормы. |
| Яйца | eggs | Продукт птицеводства. Автоцель 0 без подключённого рецепта. Учитывать в запасах, но не в днях готовой еды. |
