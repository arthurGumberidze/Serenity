# Ночной офлайн-прогон WM15

Запуск двойным щелчком: `Tools/Validation/Run-WM15-Night.cmd`.

Из PowerShell в корне проекта:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Tools\Validation\Run-WM15.ps1
```

Это обычный локальный процесс: Codex, API и токены ему не нужны. Скрипт использует установленный Unity
6000.6.4f1, импортированный проект и имеющиеся зависимости. Он не устанавливает и не скачивает пакеты.
Работа без интернета предполагает уже установленную/активированную Unity и готовый локальный cache;
скрипт не меняет настройки firewall и не отменяет требования лицензии Unity.

Перед стартом завершите текущий WM-этап и закройте Unity Editor. Уже запущенный Editor скрипт не закрывает:
ожидает освобождения проекта до 30 минут, затем записывает BLOCKED для зависимых проверок и выполняет
доступные статические проверки. Второй экземпляр этого скрипта для того же проекта не запускается.
Во время прогона не запускайте другой WM-чат, сборку или Editor для этого checkout. Компьютер должен
работать от питания; для GPU-проверок оставьте рабочий стол разблокированным и не пользуйтесь компьютером.
Скрипт запрашивает временное предотвращение сна/выключения дисплея и возвращает обычное поведение при выходе.

## Что запускается

1. Preflight, исходный commit/status и SHA-256 защищаемых файлов.
2. Компиляция проекта.
3. Все найденные публичные тестовые классы из `Assets/Game/Tests/Editor`, `Assets/Tests/Editor` и
   `Assets/Game/Tests/PlayMode`. Каждый класс запускается отдельным Unity-процессом; WM01–WM14 идут первыми,
   затем persistence/P109/U31 и остальная регрессия. Реальный список сохраняется в `fixtures.json`.
4. Новая Windows Development-сборка через существующий `U00Build.WindowsDevelopment`, с проверкой provenance.
5. Save/load smoke именно этой свежей сборки, проверка количества объектов/UI и контрольный скриншот.
6. GPU performance gates 100/300/500: по три повтора, 60 секунд прогрева и 300 секунд измерения на повтор.
   Существующий U29 harness проверяет p95, память, представления Tier и save/load, сохраняет raw frames,
   скриншоты и подробный отчёт. Ошибка одного населения не останавливает остальные.
7. Повтор SHA-256, проверка неизменности HEAD и `git diff --check`.

Текущая сборка запускает активный `p109-compact-world-v1`; предложенная V2 проверяется отдельными WM-тестами.
Этот скрипт не включает V2 в основной сцене. Поэтому Player smoke и общий U29 performance gate не являются
доказательством визуальной приёмки всей предложенной V2. WM14 сохраняет отдельный domain/LOD-профиль.

Тесты PostgreSQL без `DYNASTYGAME_PG_TEST_DATABASE` отмечаются PARTIAL; соединение не создаётся. При наличии
переменной они выполняются на заранее подготовленной тестовой базе. Пропущенные/inconclusive тесты также
не превращаются в PASS. Автоматическая миграция пользовательских сохранений не выполняется.

## Поведение после ошибки

У каждого шага есть собственный try/catch. Assertion failure, падение Unity, отсутствие XML, повреждённый
XML и timeout записываются в отчёт; очередь продолжается. После infrastructure-сбоя без XML разрешён один
повтор; упавшие assertions и timeout автоматически не повторяются. После неуспешной сборки Player-проверки
будут BLOCKED: старый exe не подставляется.

Timeout завершает только созданный процесс и найденных его потомков. Чужие Unity/Player-процессы не
завершаются. Скрипт не исправляет игровой код и не удаляет пользовательские данные. Дочерние процессы
получают отдельный `SERENITY_SAVE_DIRECTORY`, а исходные пользовательские сохранения только хешируются.
Защищаются JSON карты, World Resources, основные package/build/version-конфигурации и изначально изменённые
tracked-файлы Assets/Packages/ProjectSettings. Это не полный SHA-256 аудит всех гигабайтов art-ассетов.

Физическое отключение питания, завершение процесса пользователем или недоступный диск не позволяют
гарантировать завершение очереди. Уже завершённые шаги остаются в журнале.

## Прогресс и результат

В консоли отображаются номер шага, короткое имя, PASS/FAIL/ERROR/TIMEOUT/PARTIAL/BLOCKED. Во время долгого
процесса каждые 30 секунд появляется RUN, время текущего шага и PID. Подробные Unity логи остаются в файлах.

Каждый запуск получает новый каталог `Artifacts/WM15/night-<время>-<id>/`:

- `REPORT.md` — читаемый итог, обновляется после каждого шага;
- `STATUS.json` — текущий шаг, счётчики и heartbeat;
- `results.json` — результаты всех завершённых шагов;
- `steps.jsonl` — немедленно записываемый журнал завершённых шагов;
- `progress.log`, `plan.json`, `fixtures.json`, `protected-before.json`;
- отдельные папки шагов: stdout/stderr, Unity logs, NUnit XML, JSON, Player и скриншоты.

Код выхода: 0 — AUTOMATED_PASS, 1 — ошибки проверок, 2 — PARTIAL, 3 — ошибка самого runner.
Визуальная приёмка пользователем всегда остаётся PENDING; WM15 автоматически не помечается DONE.

По умолчанию лимит одного тестового класса — 20 минут, сборки — 60 минут, Player smoke — 5 минут,
одной performance-матрицы — 30 минут. Общий бюджет — 10 часов. По его исчерпании оставшиеся runtime-проверки
отмечаются BLOCKED, результаты и доступные финальные проверки сохраняются. Продолжительность зависит от
тестов и железа; скрипт не обещает, что весь проект уложится в одну ночь.

Пример с большим бюджетом и более частым прогрессом:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Tools\Validation\Run-WM15.ps1 -MaxHours 16 -ProgressSeconds 15 -TestTimeoutSeconds 1800
```

Проверка плана без запуска Unity:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Tools\Validation\Run-WM15.ps1 -DryRun
```

## Проверка самого runner

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Tools\Validation\Test-WM15Runner.ps1 -Repeats 2
```

Финальная версия прошла 81 assertion в Windows PowerShell 5.1 с тремя повторениями fault matrix и ещё
62 assertion в PowerShell 7 с двумя повторениями. Отдельно проверены синтаксис всех `.ps1`/`.psm1`,
реальный `-DryRun` и `.cmd -DryRun`: найдены 172 fixture / 182 шага, без запуска Unity.

Self-test компилирует маленький локальный C# fake executable штатным .NET Framework compiler, копирует
runner в отдельный `Artifacts/WM15/runner-tests/` и использует мини-проект. Настоящая Unity не запускается.
Сценарии: healthy; assertions; crash; timeout; malformed/missing/empty XML; skipped tests; failed build;
failed performance gate; missing/busy Editor; dry run; пути с пробелами/кавычками/backslash; завершение
дочернего процесса при сохранении постороннего; завершившаяся оболочка с оставшимся Player; transient lock
читателя отчёта; project mutex; защита прежних отчётов. Fault injection проходит повторно.
