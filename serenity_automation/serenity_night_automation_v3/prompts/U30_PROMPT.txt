==================================================
1. ЦЕЛЬ
==================================================

Создать надежный soak/reliability harness:
- short CI-like accelerated soak;
- restart/checkpoint recovery;
- 8+ hour unattended runner;
- invariant monitoring;
- reproducible failure artifacts.

==================================================
2. SHORT MANDATORY SOAK
==================================================

Во время U30 обязательно реально выполнить short accelerated soak разумной wall-clock длительности.

Он должен покрывать большое количество game time/steps и одновременно:
- production;
- research;
- dynasty;
- health/birth/death;
- weather;
- military;
- physical/abstract combat where feasible;
- fire/capture;
- global travel;
- strategic AI;
- events.

==================================================
3. 8+ HOUR RUNNER
==================================================

Создай отдельный command/script:
обязательно `Tools/Run-Soak-U30.ps1`.

Parameters:
- `-Seed <int>`;
- `-WallClockHours <int>` default 8 and minimum 8 for the official gate;
- `-CheckpointIntervalMinutes <int>`;
- `-OutputFolder <absolute path>`;
- optional `-ResumeFromCheckpoint <absolute path>`.

Он должен реально уметь 8h unattended, даже если current task runner не ждёт 8h.

Contract:
- exit code 0 only on a passing completed run;
- non-zero on invariant/watchdog/exception/duration/result-write failure;
- atomically write `<OutputFolder>\soak-result.json`;
- all logs/checkpoints/artifacts stay under OutputFolder supplied by the external orchestrator, outside the Git worktree;
- do not invoke Codex/OpenAI APIs from the soak runner.

`soak-result.json` mandatory fields:
- `passed` boolean;
- `seed` integer;
- `requested_wall_clock_seconds` integer;
- `actual_wall_clock_seconds` integer;
- `started_utc`, `completed_utc` ISO timestamps;
- `critical_errors`, `invariant_failures`, `watchdog_failures` integers;
- `memory_runaway_detected` boolean;
- `checkpoint_resume_verified` boolean;
- `final_state_hash` non-empty string;
- `summary` string.

==================================================
4. PROGRESS / HEARTBEAT
==================================================

Every interval write:
- wall time;
- game tick/date;
- population;
- resources;
- battles;
- AI state;
- memory;
- current hash;
- last save/checkpoint.

No silent hang.

==================================================
5. INVARIANTS
==================================================

Continuously/periodically assert:
- unique StableEntityIds;
- no duplicate canonical resource ownership;
- nonnegative quantities;
- no duplicate children/births;
- no repeated death/succession;
- no impossible dynasty refs;
- valid military membership;
- no duplicate battle participants;
- no stuck transition half-state;
- valid building ownership;
- no fire reprocessing;
- valid event exactly-once state;
- no AI invalid target loops.

==================================================
6. MEMORY / LEAK SIGNALS
==================================================

Track managed memory/alloc trends where possible.
Don't claim "no leak" from one snapshot.
Detect monotonic runaway patterns / repeated growth after GC.

==================================================
7. SAVE/LOAD CYCLING
==================================================

Soak periodically:
- save;
- reload or checkpoint-validate;
- continue.

Need prove continuation doesn't reroll/duplicate.

==================================================
8. FAILURE ARTIFACTS
==================================================

On first critical failure write:
- seed;
- tick/date;
- scenario;
- exception/assert;
- last hashes;
- latest checkpoint;
- minimal reproduction command;
- logs.

Then exit non-zero.

==================================================
9. RESUME
==================================================

Test that an interrupted soak can resume from checkpoint and continue without duplicate effects.

==================================================
10. DETERMINISM
==================================================

Short soak same seed/config repeated should end same logical hash where no external nondeterministic input.

==================================================
11. WATCHDOG
==================================================

Harness must detect stalled simulation/progress timeout and fail, not hang forever.

==================================================
12. PERFORMANCE INTEGRATION
==================================================

Reuse U29 benchmark utilities where appropriate.
Do not build another profiler system.

==================================================
13. 8H VALIDATION STATUS
==================================================

Preparation phase:
- run focused tests, short soak, deterministic repeat, checkpoint/resume and Windows build;
- create the runner and documentation;
- update U30 to IN_PROGRESS, keep NEXT_TASK on U30, commit subject beginning `U30`;
- return the preparation schema supplied by the orchestrator;
- do not mark U30 DONE and do not start U30A/U31.

External phase:
- the night orchestrator launches `Tools/Run-Soak-U30.ps1` for at least 8 hours and waits without an active Codex session;
- it validates exit code and structured result before starting the finalizer.

Finalization phase:
- a fresh Codex run reads the external structured result and supporting logs/checkpoints;
- verifies actual duration >= requested duration >= 28800 seconds and every failure counter/flag;
- updates PROJECT_STATE/TASK_GRAPH/NEXT_TASK/DECISIONS and U30_HANDOFF with exact evidence;
- commits `U30: validate 8 hour soak` and returns normal stage-result JSON.

If the external run was not executed, was shorter than 8 hours, has missing evidence or reports any critical failure, U30 remains IN_PROGRESS/NOT DONE. Never edit the DoD to turn runner readiness into completion.
