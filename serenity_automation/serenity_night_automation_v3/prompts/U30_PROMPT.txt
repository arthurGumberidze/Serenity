3. 8+ HOUR RUNNER
==================================================

Создай отдельный command/script:
обязательно `Tools/Run-Soak-U30.ps1`.

Parameters:
- `-Seed <int>`;
- `-WallClockHours <int>` default 8 and minimum 8 for the official gate;
- `-CheckpointIntervalMinutes <int>`;
- `-OutputFolder <absolute path>`;
- optional `-ResumeFromCheckpoint <absolute path>`.

Он должен реально уметь 8h unattended, даже если current task runner не ждёт 8h.

Contract:
- exit code 0 only on a passing completed run;
- non-zero at the end on invariant/watchdog/exception/duration/result-write failure;
- atomically write `<OutputFolder>\soak-result.json`;
- all logs/checkpoints/artifacts stay under OutputFolder supplied by the external orchestrator, outside the Git worktree;
- do not invoke Codex/OpenAI APIs from the soak runner.

Fail-soft evidence rule:
- a recoverable gameplay exception, invariant violation, failed checkpoint validation, Player crash or watchdog restart makes the final verdict FAIL, but must not immediately discard the rest of the night;
- append the incident to durable JSONL/text logs, preserve every completed performance/heartbeat segment and the first-failure reproduction bundle, then continue observing until the requested wall-clock deadline whenever the runner can do so safely;
- after a Player crash/hang, restart from the newest independently verified checkpoint; if it is invalid, fall back to the preceding verified checkpoint and record both failures;
- failure counters and hashes are aggregate and monotonic across restarts; never reset them when a segment restarts and never overwrite earlier evidence;
- maintain a segment/restart manifest with start/end reason, checkpoint, PID/exit code, sample counts and performance summary;
- apply bounded retry backoff so a crash loop cannot spin at full speed. Keep the orchestration heartbeat alive and continue retrying until the deadline unless an immediate-stop condition below occurs;
- immediate stop is allowed only when continued execution risks the machine/evidence or cannot record trustworthy data: output path/disk failure, inability to write the result/incident journal, explicit user cancellation, unsafe resource exhaustion, or corrupt state with no verified checkpoint/fresh-start recovery path;
- `actual_wall_clock_seconds` is real orchestration duration. Also report productive simulation duration and coverage separately; waiting/restart time cannot be disguised as successful soak time;
- a run containing any critical/invariant/watchdog incident remains `passed=false` even if later segments recover and reach the deadline.

`soak-result.json` mandatory fields:
- `passed` boolean;
- `seed` integer;
- `requested_wall_clock_seconds` integer;
- `actual_wall_clock_seconds` integer;
- `started_utc`, `completed_utc` ISO timestamps;
- `critical_errors`, `invariant_failures`, `watchdog_failures` integers;
- `memory_runaway_detected` boolean;
- `checkpoint_resume_verified` boolean;
- `final_state_hash` non-empty string;
- `summary` string.

Also include additive diagnostic fields validated by U30 tests/schema: `recoverable_errors`, `player_restarts`, `segments_completed`, `productive_simulation_seconds`, `performance_samples`, `first_failure_utc`, `last_failure_utc`, and paths/hashes for the append-only incident journal and segment manifest.

==================================================
4. PROGRESS / HEARTBEAT
==================================================

Every interval write:
- wall time;
- game tick/date;
- population;
- resources;
- battles;
- AI state;
- memory;
- interval frame count and p50/p95/p99/max frame time;
- available main/render/GPU timing, allocation rate, collection count, process CPU and working set;
- current hash;
- last save/checkpoint.

No silent hang.
Write raw or losslessly aggregated performance evidence per segment to append-only files. A restart must open a new segment file and preserve previous segments. Keep storage bounded through explicit rotation/indexing, never by overwriting older evidence.
