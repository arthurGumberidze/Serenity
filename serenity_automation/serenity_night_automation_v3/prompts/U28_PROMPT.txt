==================================================
1. ЦЕЛЬ
==================================================

Обобщить существующий narrow event foundation в reusable deterministic gameplay event system, не ломая U18.

Поддержать:
- triggers;
- targets;
- choices;
- single events and multi-node chains;
- conditions, weights and persisted cooldowns;
- deterministic outcomes;
- AI auto-resolution;
- persistence;
- off-camera;
- UI queue/history.

==================================================
2. MIGRATION, НЕ ВТОРАЯ СИСТЕМА
==================================================

Сначала изучи U18 event code.
Reuse/migrate common abstractions.
Не оставлять две competing event authorities.

==================================================
3. DOMAIN MODEL
==================================================

Engine-independent:
- EventDefinitionId
- EventDefinition
- EventInstanceId
- EventInstance
- EventTrigger
- EventChoice
- EventOutcome
- EventStatus
- EventService
- EventHistoryEntry

No GameObject refs.

Domain содержит immutable definitions/IDs/state/DTO. Mutable `EventService`, scheduler, trigger evaluation и outcome orchestration принадлежат Simulation. Presentation только отображает очередь/историю и отправляет choice command.

==================================================
4. CATEGORIES
==================================================

Минимум:
- Character/Family
- Dynasty
- Settlement
- Building
- Military/Battle
- Research/Economy

Не делать отдельные engines по категориям.

==================================================
5. TRIGGERS
==================================================

Поддержать data-driven trigger conditions:
- tick/date;
- state predicate;
- after canonical event/hook;
- probability/weight with deterministic RNG.

No per-definition Update.

Каждая definition явно задаёт eligibility conditions, integer weight, cooldown policy и optional next-node transitions. Catalog validation rejects missing nodes, duplicate IDs, impossible next references and unbounded cycles.

==================================================
5A. CHAINS AND COOLDOWNS
==================================================

Минимум одна representative Stone Age event chain должна иметь 2+ nodes и условный переход после player/AI choice.

Persist:
- chain instance/root ID;
- current node;
- visited/resolved node markers;
- next eligible tick/cooldown checkpoint;
- pending choice and deterministic sequence.

Save/load between nodes must continue the same chain without re-offer, skipped outcome or reroll. Cooldown is evaluated from canonical ticks and cannot be reset by tier/mode/load changes.

==================================================
6. DETERMINISTIC RNG
==================================================

Use U14 keyed RNG:
world seed + event definition + target IDs + eligible tick/sequence.

Same state => same offered/resolved event.

Collection order independent.

==================================================
7. EXACTLY ONCE
==================================================

Event may become:
Eligible -> Offered/Pending -> Resolved/Expired.

Save/load/off-camera catch-up must not:
- offer duplicate instance;
- apply outcome twice;
- reroll resolved outcome.

==================================================
8. TARGETS
==================================================

Stable refs only:
Character ID, Dynasty ID, Building ID, MilitaryUnitId, Settlement/Location ID, BattleId.

Missing target handled cleanly.

==================================================
9. PLAYER CHOICES
==================================================

At least one event with 2+ choices.
Pending choice persists across Save/Load.
Outcome applied only after valid choice.

UI from U27 displays:
title/description/targets/choices/outcome.

==================================================
10. AI CHOICES
==================================================

AI settlement cannot wait for player UI.
Deterministic choice policy:
- scoring;
- stable tie-break.
No cheating.

==================================================
11. OFF-CAMERA
==================================================

Events can trigger/resolve for remote AI/location without materialization.

Player-targeted choice events may queue pending until player interaction.

==================================================
12. CONTENT SET
==================================================

Add only ~8–15 representative Stone Age events.
Examples may cover:
- family dispute/support;
- minor settlement resource opportunity/cost;
- research insight;
- military morale incident;
- building mishap;
- dynasty family matter.

Do not write hundreds.

==================================================
13. OUTCOME API
==================================================

Outcomes call existing canonical services.
Do not directly mutate:
health/resources/building owner/combat/dynasty if service exists.

==================================================
14. U18 COMPATIBILITY
==================================================

Existing health/family events either:
- run through generalized system,
or
- use shared common event primitives cleanly.

All U18 tests must remain valid.

==================================================
15. EVENT HISTORY
==================================================

Persist compact history:
- instance ID;
- definition ID;
- targets;
- offered/resolved ticks;
- choice;
- outcome summary.

No giant narrative logs.

==================================================
16. UI
==================================================

U27:
- pending event indicator;
- event queue/list;
- detail modal/panel;
- choices;
- resolved notification/history.

No debug raw JSON in normal UI.

==================================================
17. SAVE/LOAD
==================================================

Persist:
- pending events;
- processed/eligibility markers;
- history;
- deterministic sequence counters;
- unresolved choice.

Preserve all prior snapshots.

==================================================
18. INVALID STATES
==================================================

Handle:
- missing target;
- no valid choice;
- choice after resolution;
- duplicate event ID;
- bad definition;
- cyclic/recursive trigger chain runaway.

Add guard against infinite immediate event loops.
